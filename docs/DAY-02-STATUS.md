# 2일차 인계

## 완료한 코드

- 계정·연결 환경·본인 확인·잔액·포지션·체결 도메인 타입
- 주문 상태 전이: 타임아웃, 부분 체결, 취소 경합, 중복/역순 알림, 정정 격리
- 입출금 상태 전이: 처리 중, 완료, 실패, 취소, 반환
- 계정 소유권·앱/거래소 제한 상태·권한 검사 기반 함수
- 11개 테이블의 Drizzle 스키마와 최초 SQL 마이그레이션 파일
- 사용자/계정/거래소 외래키, 주문·체결·입출금·이벤트 중복 제약
- 1일차 4개 + 상태/계정 18개 + SQLite 11개 = 33개 테스트

## 검증

33개 테스트 통과. 메모리 SQLite에 실제 생성 SQL을 적용하여 외래키·CHECK·UNIQUE·롤백·조회 인덱스를 검증했다. 운영 DB에 적용한 것은 아니다.

## 아직 연결하지 않은 것

로그인·영구 저장 API·실제 거래소 이벤트·체결·입출금은 미구현. 상태 함수와 스키마는 다음 일차에서 연결할 기반이다. 라이브 주문 API는 계속 503을 반환한다.
UI는 1일차 거래 탐색 화면을 유지하고 개발 진행 표시만 Day 02로 갱신했다.

## 다음 작업 — 3일차

제휴 심사용 제품 설명, 역할/책임, 데이터·주문 권한, 비용·수익 배분 질문서를 준비한다. 외부 발송은 별도 명시 요청 후 진행한다.
개발 계획에 따라 4일차에 인증, 5일차에 사용자별 영구 저장과 인가를 구현한다.
