# 1일차 인계

## 구현 완료

- 시장 목록(6개 명시적 fixture), 카테고리, 검색, 세션 내 관심 시장
- 상세 규칙/계약 정보, 샘플 차트, YES/NO 선택
- 정수 계약 수량 입력과 서버 견적 API, 검토 모달
- 거래소 독립 타입과 조회/견적 Provider 인터페이스
- 실거래 POST /api/orders는 항상 503으로 차단
- 계정 연결 안내. 실계정 개설이나 자금 수취 없음
- 30일 일별 계획과 제휴사 연결 지침

## 확인 결과

- node:test 4개 통과: 금액 보존, 잘못된 가격/수량 거부, 정수 단위 계산, 실거래 차단
- TypeScript 검사 통과
- HTTP 검증: 시장 6개, YES/NO 견적, 잘못된 요청 5종 거부, 실거래 503
- 브라우저: 목록 → 상세 → 100계약 → 서버 응답 → 검토 모달. 64¢ × 100 = $64, 지급 예시 $100, 실거래 버튼 비활성
- WebMCP 검색: inflation 입력 시 1개 표시, 숫자 입력 오류 확인

## 다음 작업: 2일차

계정/거래/자금 데이터 모델과 상태 전이 명세를 설계한다. 인증과 저장소는 파트너 역할과 별도로 준비하되 실제 고객자금 원장의 원본은 파트너가 되도록 설계한다.

## 명확한 미완료 범위

- 로그인, 사용자 데이터 영구 저장, 실제 체결, 입출금, 실시간 시세, KYC, 수수료, 제휴, 수익화는 아직 없음.
- 실거래 연결은 API 주소 변경만으로 되지 않는다. 어댑터·권한·인가·보안·대조·인증이 필요하다.
- 서버 견적은 개발용이고 실행 가능한 가격이 아니다. 금액 스케일은 현재 1센트/정수 계약만 지원한다.
