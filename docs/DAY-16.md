# Day 16 — verification visibility and trading eligibility restrictions

`/account/eligibility` distinguishes Google login, active Event profile, identity/age verification, location eligibility and live trading/funding readiness. No identity or location provider is connected, so those checks are explicitly unavailable and real trading is always false. Login is never treated as KYC. No documents, date of birth, identity numbers or bank information are collected. This is application policy infrastructure, not a determination that a user legally qualifies to trade.

`/admin/eligibility` lets the existing configured active administrator restrict or restore practice trading with a required reason and confirmation. It lists accounts in pages of 20, current revision and the latest 30 audit records. Only the administrator can read internal reasons and history. User eligibility exposes only restriction state. An immutable audit receipt and the restriction row are committed atomically. Expected revisions reject stale writes; request IDs deduplicate retries and reject changed intent. Migration 0011 creates an empty restrictions table, without modifying existing users or balances.

Restricted active accounts can view portfolios and cash journals, cancel buys and sell reservations, and retain holdings. New buy orders, new sell reservations and matching involving the restricted account are blocked. The buy/sell admission predicates and the match commit's repeated candidate query check restrictions inside their atomic writes, so a stale prior eligibility read cannot authorize a new fill. Existing reservations are not automatically cancelled. Removing the restriction permits otherwise eligible old orders to match again; UI confirmation explains this. No restriction state enables real trading or bypasses existing account suspension.

Verification providers and jurisdiction/age policies must be separately integrated before live eligibility can ever become true. Administrator restriction removal is not verification approval. Existing live order/funding routes remain disabled; neither administrative controls nor client payloads can activate them.

Validation: 151 automated tests including admin authorization, account isolation, audit rollback, stale/concurrent edits, idempotency conflict, matching selection/commit race, restricted buys/sells, retained holdings and cancellation. Disposable local HTTP accounts verify authenticated eligibility, non-admin and cross-origin rejection, actual restricted order responses, read/cancel access and page rendering. Production users are not changed by verification tests.
