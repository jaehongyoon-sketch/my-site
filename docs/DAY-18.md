# Day 18 — practice reconciliation

`/practice/reconciliation` compares all owned saved practice records in one D1 batch snapshot. It reports passed, mismatched, not-applicable and not-started states, with a checked timestamp, total comparisons/failures and up to 50 discrepancy details. Detail limits never truncate aggregate checks. Errors clear the prior successful result. References expose only owned orders, events and already associated match IDs, not counterpart identities.

Sixteen check categories compare available/reserved/spent funds with the cash journal, the one-time grant, cash reservations with order reservations, per-order matched quantities/principal/fees/remaining holds, fill receipt completeness/ownership/cost/fees, YES/NO pair participants and $1 principal, share reservation journal/receipts and sell quantities within matched holdings. Expected execution quantities and costs are independently reconstructed from matches joined to owned orders rather than trusting order progress or the limited recent-fill display. Both per-contract exact fees and migrated legacy rounded-per-order fees are supported. Amount comparisons use integer 1/400-cent units.

The implementation uses separate bounded-result SELECTs inside the same transaction to respect the Workers SQLite compound SELECT limit. Every applicable record participates in aggregate checks. This is read-only reconciliation: it does not release expired reservations, collect trade events, place orders, repair rows or move funds. Expired open reservations are compared against their recorded lifecycle state until the existing portfolio/order lifecycle releases them. Holdings are fill-derived, so checks compare those matched holdings against recorded share reservations rather than inventing a second authoritative position table.

The authenticated, active-profile GET endpoint rejects account IDs and all filters. A trading-restricted active account can still run checks. Suspended/closed profiles cannot. Responses are private/no-store. No schema migration, production fixture or customer data mutation is introduced. These checks diagnose internal practice consistency; they are not settlement, real-money reconciliation, a full forensic audit or proof that external funds exist.

Validation: 169 automated tests total, including grant-only/no-account state, partial matching, price improvements, cancellation, sell release, expiry, exact sub-cent and legacy fees, cash corruption, missing own/counterpart receipts, order projection corruption, missing share receipts, overselling, account isolation and >50 mismatch details. Local HTTP verification exercises the Workers SQLite path, authentication, restricted-account access, injected discrepancies, unaffected other accounts and restored disposable test fixtures.
